# HistoryNotice 归属表

更新时间：2026-05-19

## 1. 这份表是干什么的

这份表不是知识正文。

它的作用只有一个：

把 `Notice/HistoryNotice` 里的历史笔记先建立成一份可执行的整理索引，明确每篇笔记后续应该流向哪里、该怎么处理、是否值得深提炼。

当前这一版以**文件名判断 + 少量抽样确认**为基础，属于第一轮轻整理结果。  
它适合做后续工作排期，不适合作为某一系统的最终事实来源。

## 2. 字段说明

- `目标知识包`：后续优先整理进哪个知识主题。
- `处理方式`：
  - `提炼成知识文档`：适合沉淀为稳定知识。
  - `拆分后进入知识包`：原文不直接迁移，需要拆出结论。
  - `进入问题库/已知问题`：适合沉淀为排查或故障卡。
  - `保留为参考研究`：有价值，但不应混同为项目当前事实。
  - `仅保留历史档案`：暂时不进入知识库正文。
- `备注`：说明它更接近什么类型，或者为什么这样分。
