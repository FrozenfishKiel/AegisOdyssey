# StateTree AI 当前决策与边界

更新时间：2026-05-14  
适用范围：`StateTree AI` 当前排查与改动边界。  
目标：明确当前阶段哪些路优先走，哪些路当前不走。

## 1. 文档定位

这份文档不是规则文档，也不是问题清单。  
它回答的是：

- 这轮为什么这样组织知识
- 为什么某些技术路线暂时不做
- 为什么排查顺序要固定成现在这样

如果没有这份文档，后面无论是人还是 AI，都很容易每次重新发明一套“理论上更优雅”的做法，最后把任务拉散。

## 2. 当前阶段的总决策

### 决策一：当前优先覆盖 C++ 运行时真相源

原因：

- 当前最稳定、最适合承载真相的是 C++ 主链路
- StateTree 资产、蓝图配置、策划参数虽然重要，但当前阶段优先级低于运行时真相链

影响：

- 当前排查优先围绕 Controller、Component、Evaluator、Task、Condition
- 当前不主动把编辑器资产细节扩成完整知识域

### 决策二：当前目标是“降低定位成本”，不是“替代代码阅读”

原因：

- `StateTree AI` 的真实问题很多仍然需要下钻到代码和绑定关系
- 单靠领域说明无法替代对具体节点代码和绑定关系的确认

影响：

- 优先从定位入口、状态真相源和高风险误判点切入
- 不把当前材料当成完整实现替代品

### 决策三：默认以“状态真相源 -> 生命周期 -> 消费节点”为排查顺序

原因：

- 当前链路里，很多表面故障其实不是节点逻辑错，而是状态没写对、没清掉，或者树根本没跑起来

影响：

- 默认先查 `AAOAIPlayerBotController`
- 再查 `UAOStateTreeComponentBase` / `UAOAILogicStateTreeComponentBase` / `OnPossess()`
- 最后再看具体 Task / Condition / Evaluator

### 决策四：当前不追求“大而全”，而是优先收窄范围

原因：

- `StateTree AI` 涉及资产、蓝图、感知、移动、标签、装备等多个层面
- 当前阶段同时展开所有子域，诊断成本会快速上升

影响：

- 当前范围先收窄在高频、稳定、可验证的运行时主链
- 其他子域在被重复命中前不优先展开

### 决策五：默认不在外围入口打补丁，优先修状态边界或主链路

原因：

- `StateTree AI` 这类问题常见误修方式，是在外围加临时 if、局部缓存、防重逻辑
- 这些做法往往能遮住现象，但不能收敛状态真相

影响：

- AI 如果给出“先在外层补个判断”的方案，必须先回看这份文档
- 优先考虑 Controller 状态、组件生命周期、主消费链路上的修法

## 3. 后续扩展边界

如果后续持续出现下面这些问题，说明当前材料覆盖范围不足：

- 某类资产路径总被重复解释
- 同一批 Task / Condition 总被重复检索
- 同一个状态边界总被问
- 不同人接手同类问题时，仍然不知道先看哪

到那时再考虑新增：

- `ASSET_MAP.md`
- `TERMS.md`
- 某类子系统专项文档

在那之前，不扩展。
