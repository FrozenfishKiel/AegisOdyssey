## 2. 本轮已经明确、不能再理解错的设计结论

### 2.1 采集的本质语义

采集现在已经明确按下面这套语义走：

- 采集要像战斗一样理解。
- 不是“预选一个采集目标，然后对它发请求”。
- 而是“工具挥击 -> 命中对象 -> 从被命中的对象身上结算资源”。

这几点已经明确，不要再退回旧理解：

- **不能从玩家摄像机发采集判定。**
- **采集 Trace 必须来自工具自身的 Start / End Socket。**
- **TargetActor 不是让状态树提前配置一个采集对象。**
- **TargetActor / TargetComponent 只是这次真实命中后解析出来的运行时上下文。**

### 2.2 采集与战斗要尽量共用思路，但不是强行共用类

用户已经明确接受下面这条思路：

- 动画驱动命中窗口
- 工具自身轨迹判定
- 服务端统一重判定和结算
- 命中对象后再推进对象自身进度

但用户也明确说过：

- 开发阶段为了可读性，采集相关的代码可以单独写
- 不要为了“看起来复用”把阅读体验做烂

所以当前策略是：

- **语义与链路参考战斗**
- **实现保持采集自己的代码入口**

### 2.3 节点耗尽后的处理必须走统一入口 + 多态

用户明确要求：

- 公共采集系统不要写死树的逻辑
- 不能把“树会倒”误当成采集系统唯一耗尽表现
- 要有统一耗尽入口
- 不同采集对象通过子类各自处理自己的耗尽反应

当前已经按这个方向落地：

- 公共层只负责节点状态切换与生命周期分发
- 树、石头、草、矿脉等对象以后走各自子类

### 2.4 文件目录不能再按技术类型平铺

这次已经明确：

- 不要继续把采集节点长期放在 `Actors/`、`Components/`、`Interfaces/`、`Types/` 这种机械平铺目录里
- 以后默认按“公共核心层 + 具体对象层”组织

当前已经重构为：

```text
Harvest/
  Abilities/
  Core/
  Cue/
  Definition/
  Fragments/
  Items/
  Nodes/
    Tree/

```

这条是**硬约束**，后面石头、草、矿脉请继续按：

```text

Harvest/Nodes/Bush/
Harvest/Nodes/Ore/
```

不要再新开一个平铺 `Actors/` 往里塞。

## 3. 本轮已经落地的内容

## 3.1 采集主链已经能工作

当前采集主链入口：

- `Source/AegisOdyssey/Harvest/StateTree/STT_PlayHarvest.h`
- `Source/AegisOdyssey/Harvest/StateTree/STT_PlayHarvest.cpp`
- `Source/AegisOdyssey/Harvest/Abilities/GA_Harvest.h`
- `Source/AegisOdyssey/Harvest/Abilities/GA_Harvest.cpp`

当前链路是：

1. `StateTree` 发起采集动作
2. 下发 Montage、工具快照、输入标签等本次动作配置
3. `GA_Harvest` 播放采集蒙太奇
4. 命中窗口打开时，由 `UAT_WaitHarvestHit` 提交一次真实采集命中
5. `GA_Harvest` 从工具 Socket 解析 Trace
6. 命中对象后解析出 `TargetActor / TargetComponent`
7. 服务端进入 `UAOHarvestResolver::ResolveHarvestRequest(...)`
8. 通过后先提交奖励，再推进节点进度，再触发生命周期与反馈

当前不是这样：

- 不是摄像机判定
- 不是 Delay 到点就自动采
- 不是状态树先挑目标再强灌给采集系统

## 3.2 服务端统一结算已经落地

主文件：

- `Source/AegisOdyssey/Harvest/System/AOHarvestResolver.h`
- `Source/AegisOdyssey/Harvest/System/AOHarvestResolver.cpp`

当前已经明确的进度公式：

```text
RequestedProgress = BaseHarvestPower * max(0, ProgressMultiplier)
AppliedProgress   = clamp(RequestedProgress, 0, PreviousProgress)
RemainingProgress = max(0, PreviousProgress - AppliedProgress)
```

语义是：

- `BaseHarvestPower` 来自工具 `HarvestToolFragment`
- `ProgressMultiplier` 来自对象对当前工具语义的响应
- `YieldMultiplier` 只影响掉落数量，不影响进度推进

关键配置位置：

- 工具基础采集强度：`Source/AegisOdyssey/Harvest/Fragments/AOHarvestToolFragment.h`
- 对象总进度 / 掉落 / 工具响应：`Source/AegisOdyssey/Harvest/Definition/AOHarvestableDefinition.h`

这轮最浪费时间的不是目录本身，而是历史文件里有大量乱码中文注释。

问题表现：

- 注释和 `UCLASS` / `USTRUCT` / `if (...)` / 变量定义粘在同一行

- 实际会导致：
  - `UHT` 误以为宏在被跳过的块里
  - `generated.h` 缺失
  - 变量“未声明”
  - 分支“不可达”

这轮已经修掉了一批关键文件的粘连问题，但要明确：

- **Harvest 里仍有不少历史乱码中文注释没完全洗净**

- `UHT` 类不存在

## 4.2 Harvest GameplayCue 目前走的是“直播兜底链”

之前明确踩到过：

- 项目只扫描了技能类 `GameplayCueNotify` 资源路径
