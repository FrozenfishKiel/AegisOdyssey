### 距离匹配
距离匹配会告诉动画从哪里开始播放，因为每一帧都要更新角色的停止位置预测，所以我们在OnUpdate可以这么创建预测节点

### 距离匹配
删掉AdvanceTime，并添加AdvanceTimeByDistanceMatching，目的是通过距离匹配来选择播放时间，这相当于AdvanceTime和距离匹配配合了

![](https://cdn.nlark.com/yuque/0/2025/png/57222916/1765309951240-fa68584c-0097-483a-80b2-193561ed9afa.png)

它需要一个Distance Traveled作为输入，这个是_**角色每一帧实际移动**_的距离，因此我们_**需要计算角色上一帧和这一帧的位置之间的差值**_，会"看"你移动了多少 ：如果你跑得快，动画就播得快；跑得慢，动画就播得慢

+ AdvanceTime = 固定速度播放视频
+ AdvanceTimeByDistanceMatching 中的 AdvanceTime = 根据实际移动智能调整播放速度
+ ![在线程安全更新中调用这个函数](https://cdn.nlark.com/yuque/0/2025/png/57222916/1765343899888-cb01c785-38f2-44d6-b782-ea75b87040a3.png)

该节点的计算原理：



角色实际移动距离 = 2米

动画距离曲线显示：从当前时间点开始，移动2米需要1.2秒

系统计算：有效播放速率 = 2米 / (1.2秒 × 每帧时间)

然后按照这个播放速率推进动画时间。



使用惯性化能让衔接规则变得自然，但会加重CPU的负担

![](https://cdn.nlark.com/yuque/0/2025/png/57222916/1765310772582-8e4c876f-492e-4d1f-b33a-9dd119d811a7.png)

+ 角色从站立状态突然开始奔跑
+ 角色在移动中突然改变速度（加速/减速）
+ 角色在复杂地形上移动时速度不稳定



2. 防止过度缩放导致的异常动画

本质问题： 步幅缩放值超出合理范围导致的角色动画失真

具体场景：

+ 角色移动速度远快于动画根运动速度（步幅缩放值过大）
+ 角色移动速度远慢于动画根运动速度（步幅缩放值过小）
+ 网络同步延迟导致的异常速度值



3. 处理根运动速度阈值附近的抖动

急转发生在_**角色当前的速度方向和加速度方向不一致**_的情况，例如你正在向前跑但突然想向后跑，或者正在向前行驶的汽车突然挂了倒挡向后开，那么这一瞬间需要插入动画，因此我们规定：当速度方向与加速度方向_**角度**_不一致，则播放急转动画

因此在进入急转动画的条件中，我们首先归一化，然后计算速度方向和加速度方向角度的点积

![](https://cdn.nlark.com/yuque/0/2025/png/57222916/1765349857309-edbc2f34-a3b2-4265-b863-c872b27cf5f0.png)

归一化后的向量只表示 方向 信息，不包含 长度 信息。这在很多情况下非常有用，比如方向向量：表示物体的朝向，法线向量：表示表面的朝向，光照方向：表示光线的方向

假设我们有一个向量 V = (x, y, z) ，它的长度（模长）是：

长度 = √(x² + y² + z²)



归一化后的向量就是：

单位向量 = (x/长度, y/长度, z/长度)

这样，新的向量长度就变成了1。



点积 是两个向量之间的一种数学运算，结果是一个标量（单个数值）。它表示两个向量在方向上的相似程度

根据点积的结果，我们可以判断两个向量的方向关系：

点积 > 0 ：两个向量方向基本相同（夹角 < 90°）；

点积 = 0 ：两个向量垂直（夹角 = 90°；

点积 < 0 ：两个向量方向基本相反（夹角 > 90°）

## 关于惯性化（Inertializetion）
惯性化Inertializetion 是虚幻引擎中一种高级的动画过渡技术，主要用于解决动画切换时出现的"跳跃"或"突变"问题。比如在开车时突然急转弯，身体会因为惯性而向相反方向倾斜。惯性化就是模拟这种物理现象，让动画切换时有一个自然的"惯性"过渡，而不是生硬的直接切换，它通过记录当前动画的运动状态，并基于这些状态计算平滑的过渡曲线，让新动画从当前的运动状态开始，从而实现自然的动画过渡效果。



这种技术在《战争机器》等游戏中首次大规模应用，现在已经成为现代游戏动画系统的标准功能之一。
