# Delivery Checklist

用途：每次 UE Harness 任务交付前逐项检查。只要存在未完成项，就不能把任务说成“完成交付”，只能说明当前降级状态。

## 1. Context

- [ ] 已读取 `ue-harness/core/harness-definition.md`
- [ ] 已读取本任务相关的 `Project Adapter`
- [ ] 已读取对应 `Knowledge` 包
- [ ] 已检查工作区版本状态，未覆盖用户改动
- [ ] 如涉及历史原因，已读取相关版本历史

## 2. Implementation

- [ ] 本轮最小交付已完成
- [ ] 主 agent 是唯一代码写入者
- [ ] 核心函数有中文注释
- [ ] 新增属性有中文注释
- [ ] 蓝图暴露、配置、DataAsset 或编辑器属性已说明用途

## 3. Documentation

- [ ] 已补技术文档，或明确说明本轮不需要新增技术文档的原因
- [ ] 技术文档包含设计说明、调用链、风险边界
- [ ] 涉及蓝图或编辑器操作时，已补接线说明
- [ ] 已判断产出属于 `Knowledge` 还是 `Notice`

## 4. Validation

- [ ] 已记录编译结果，或明确未编译原因
- [ ] 已记录自动化测试结果，或明确未运行原因
- [ ] 已补冷启动测试步骤
- [ ] 已写预期结果和实际结果/当前状态
- [ ] 已列出未覆盖项

## 5. Memory

- [ ] 已补任务记忆或说明无需沉淀的原因
- [ ] 已记录新增稳定事实
- [ ] 已记录阶段性提醒或 `Notice candidate`
- [ ] 已判断是否需要升级到规则、清单或脚本

## 6. Handoff

- [ ] 交付说明包含变更范围
- [ ] 交付说明包含验证证据
- [ ] 交付说明包含降级项
- [ ] 交付说明不把未验证内容写成已完成事实
- [ ] 下一步建议没有越过当前实施步骤
