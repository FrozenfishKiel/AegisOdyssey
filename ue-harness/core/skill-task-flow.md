# Skill And Task Flow

## 作用

`Skill` 解决的是“AI 接到任务以后，应该按什么顺序做”。

它不是单条规则，也不是结果验收，而是把高频交付动作固化成稳定流程。

如果没有这一层，AI 每次都可能临时拼装自己的执行顺序：

- 只写代码，不补文档
- 只改实现，不做验证
- 只说设计，不落记忆

Harness 的目标不是让 AI 会做某一段，而是让它每次都沿着同一条主链推进。

## Skill 的边界

Skill 的职责：

- 固定任务进入 Harness 后的主顺序
- 防止跳步
- 保证交付动作能重复执行

Skill 不负责：

- 替代项目上下文
- 替代验证结果
- 替代长期记忆

## UE Harness 的默认主链

对 UE 项目，入口 skill 默认应推动任务经过下面这条主链：

1. 读取规则
2. 读取项目上下文
3. 重述任务并拆解需求
4. 标出影响范围
5. 确认项目可见性和历史上下文是否足够
6. 给出实现思路
7. 完成实现
8. 同步补注释
9. 输出蓝图交互说明
10. 生成技术文档
11. 生成测试文档
12. 记录任务记忆
13. 把本次任务纳入开发自循环

## 关键要求

Skill 在这个能力包里的意义，不是让任务看起来更规范，而是让 AI 每次都默认经过：

- 输入
- 执行
- 验证
- 沉淀
- 回流

因此，Skill 必须明确：

- 这是流程，不是 prompt
- 这是稳定顺序，不是某次会话里的临时安排
- 这是 Harness 的主链，而不是实现细节备忘录
