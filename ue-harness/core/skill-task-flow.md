# Skill And Task Flow

## 作用

`Skill` 解决的是“AI 接到任务以后，应该按什么顺序做”。

它不是单条规则，也不是结果验收，而是把高频交付动作固化成稳定流程。

如果没有这一层，AI 每次都可能临时拼装自己的执行顺序：

- 只写代码，不补文档
- 只改实现，不做验证
- 只说设计，不落记忆

Harness 的目标不是让 AI 会做某一段，而是让它每次都沿着同一条主链推进。

## Skill 的边界

Skill 的职责：

- 固定任务进入 Harness 后的主顺序
- 防止跳步
- 保证交付动作能重复执行

Skill 不负责：

- 替代项目上下文
- 替代验证结果
- 替代长期记忆

## UE Harness 的默认主链

对 UE 项目，入口 skill 默认应推动任务经过下面这条主链：

1. 读取规则
2. 读取项目上下文
3. 重述任务并拆解需求
4. 标出影响范围
5. 确认项目可见性和历史上下文是否足够
6. 给出实现思路
7. 完成实现
8. 同步补注释
9. 输出蓝图交互说明
10. 生成技术文档
11. 生成测试文档
12. 记录任务记忆
13. 把本次任务纳入开发自循环

## 关键要求

Skill 在这个能力包里的意义，不是让任务看起来更规范，而是让 AI 每次都默认经过：

- 输入
- 执行
- 验证
- 沉淀
- 回流

因此，Skill 必须明确：

- 这是流程，不是 prompt
- 这是稳定顺序，不是某次会话里的临时安排
- 这是 Harness 的主链，而不是实现细节备忘录

## Direct Execution Mode 主链

当用户明确要求直接执行、不要停、先解决问题时，默认主链必须压缩为：

1. 读取 `git status --short`，确认不要覆盖无关用户改动。
2. 只读取完成当前改动必需的源码和项目知识。
3. 立即实施最小闭环代码改动。
4. 对删除型重构建立 Deleted Symbol Checklist，并用 `rg` 清零旧符号。
5. 能编译就编译；不能编译就运行静态扫描、说明缺失的构建入口，并给出人工验证入口。
6. 最终交付时说明改了什么、验证了什么、哪些验证因环境缺失没有跑。

Direct Execution Mode 中禁止把以下事项作为动手前暂停理由：

- 子 agent 不可用。
- 文档模板缺失。
- 编译工具不在 PATH。
- 蓝图或编辑器连接不可机器读取。
- 需要写长计划或长报告。

这些事项只能作为最终交付的降级说明，除非它们会导致当前代码编辑不安全。

## 删除型重构规则

当任务目标是“删掉职责、删掉字段、瘦身、不要包装语义、不要保留旧概念”时，流程必须以删除闭环为中心：

1. 列出要消失的类型、字段、函数、配置名和日志名。
2. 先删定义，再修所有编译引用。
3. 每轮修改后用 `rg` 搜旧符号。
4. 旧符号未清零前，不进入文档整理或方案解释。
5. 如果某个旧名必须保留用于资产迁移，只能以 CoreRedirect / PropertyRedirect 的形式保留，并在交付中说明。

## 编码和补丁失败规则

如果遇到 invalid UTF-8、乱码注释、`apply_patch` 上下文失配，最多重试一次小补丁。

第二次仍失败时，立即切换策略：

1. 从 `git show HEAD:path` 或当前文件按行读取重建。
2. 只叠加必要语义改动。
3. 检查 `//.*UPROPERTY`、`//.*UFUNCTION`、`//.*\t`，避免注释吞掉 Unreal 宏或声明。
4. 检查被删除符号是否仍残留。

不要在同一处 patch 失败上反复停顿或解释。
