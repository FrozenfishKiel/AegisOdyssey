# Version Control

## 作用

版本控制在这套能力包里不是附属条件，而是顶层组成部分。

原因很简单：

- 没有版本控制，AI 只能看到当前快照
- 有了版本控制，AI 才能理解项目为什么会变成现在这样

这正是原文把“接入版本控制”单独作为小团队第二步的原因。

## Harness 为什么必须依赖版本历史

Harness 要求 AI 不只是“会做当前这一步”，而是要能进入持续开发。

如果没有版本历史：

- AI 看不到决策演进
- AI 看不到某条链路为什么存在
- AI 看不到某次修复为什么要这样做

这会让项目理解始终停留在“当前状态截图”。

## 最低要求

对于要接入这套能力包的项目，至少要满足：

- 项目处于版本控制之下
- 或者至少有清晰的任务演进记录可以替代部分历史可见性

如果两者都没有，这套 Harness 仍可部分工作，但只能算：

“有规则的临时协作”

还不算完整的 Harness 闭环。
