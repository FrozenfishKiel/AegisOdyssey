# MCP And Project Visibility

## 作用

`MCP` 在这套能力包里解决的是：

> AI 能看到什么项目上下文？

如果 AI 看不到真实项目结构、验证结果和演进历史，它就只能靠人临时描述来猜。
这会让 Harness 退化成“带规则的盲飞”。

因此，`MCP / Project Visibility` 必须是本体层，不是边角配置。

## 核心定义

在这个场景里，MCP 不应被收缩成某个协议名词，也不应只写成“adapter 里放路径”。

它的本质是：

- AI 可见范围
- 项目上下文读取入口
- 真实工程事实的暴露层

## UE 项目里的最小可见范围

对于 UE 项目，AI 至少应能读到：

- 代码
- 规则文件
- Task Flow / Skill 文件
- 技术文档
- 测试文档
- 测试结果
- 编译结果
- 运行日志
- 资源与配置
- 蓝图接线信息
- 编辑器操作信息
- 版本历史
- 任务演进记录

## 三类关键事实

这层真正要保证的，是 AI 能拿到三类事实：

1. 结构事实  
   项目现在长什么样，模块边界是什么。

2. 验证事实  
   本次改动通过了什么、没通过什么、还缺什么。

3. 历史事实  
   项目为什么会演进成今天这样。

## 和 Adapter 的关系

`Project Adapter` 可以帮助能力包定位这些信息放在哪里，但 adapter 只是接线层。

不能把 adapter 当成 MCP 本体。

MCP 回答的是“AI 能看到什么”；
adapter 回答的是“这些东西在这个项目里具体放哪儿”。
