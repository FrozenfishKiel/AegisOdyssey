# Script And Validation

## 作用

`Script` 解决的是“做完了没有”。

它是 Harness 里最重要的事后兜底层。
没有这一层，AI 说“已经完成”就只能靠人主观相信。

在这套能力包里，验证层必须明确：

- Rule 负责事前预防
- Script 负责事后验证

## Script 的边界

Script 的职责：

- 对任务结果进行检查
- 把“我觉得做完了”变成“可以被复查的结果”
- 逐步接住已经反复出现的错误模式

Script 不负责：

- 替代设计判断
- 替代项目上下文
- 替代最终人工体验判断

## UE 场景下的现实约束

在 Unreal Engine 项目里，验证不能一开始就假设全自动。

原因包括：

- 蓝图接线不完全是纯文本问题
- 编辑器操作有人工步骤
- 运行时表现、手感和视觉效果不能仅靠编译结果判断

所以第一版的正确策略不是“全自动化”，而是：

1. 先建立检查清单
2. 再补安全脚本
3. 再逐步把高频错误编码成自动验证

## UE 验证层的最小覆盖

即使暂时没有完整自动化，验证层至少应覆盖：

- 编译结果
- 测试结果
- 关键日志
- 冷启动测试步骤
- 蓝图接线验证点
- 编辑器操作验证点
- 未覆盖项说明

也就是说，Script 在这个场景里不应狭义理解成“只有 Python 或 shell 脚本”，而应理解成完整的验证层。

自动脚本只是其中一部分。
