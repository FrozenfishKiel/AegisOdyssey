# Harness Definition

## 定义

`Agent = Model + Harness`

在这套能力包里，`Model` 是能力来源，`Harness` 是让能力稳定工作的工程系统。

Harness 不是 prompt，不是长提示词，也不是几份模板的堆叠。
Harness 的真正含义是：

- 把规则固定下来
- 把任务流程固定下来
- 把验证机制固定下来
- 把项目可见性固定下来
- 把任务记忆固定下来
- 把版本历史纳入上下文
- 把每次任务放进开发自循环

没有 Harness 的模型，哪怕单点能力很强，也仍然容易退化成：

- 规则靠人反复提醒
- 上下文只存在聊天记录里
- 任务做完即断
- 下一轮重新从零开始

## 目标

这套 UE Harness 的目标不是让 AI 偶尔帮忙生成一段代码，而是让它在 Unreal Engine 项目里成为一个稳定、可追踪、可复用的工程执行者。

因此，这套能力包优先解决的是：

1. 规则如何在任务开始前生效
2. 任务如何按稳定流程推进
3. 结果如何被验证
4. AI 能看到哪些项目上下文
5. 这次任务学到的东西如何留到下次
6. 版本历史如何变成 AI 的长期上下文
7. 每次任务如何进入下一轮自循环

## 原文落点

原文讲的不是“模型不够强”，而是“鞍具没有搭好”。

所以这套文件的边界必须明确：

- 它不是通用 AI 开发理论
- 它不是 Unreal Engine 插件
- 它不是一次性任务提示词
- 它不是只围绕多 agent 编排的调度器

它是一套面向 `Codex / Claude Code` 的 UE 工程 Harness。

## 三步法适配说明

原文给小团队的落地路径是：

1. 先做原型，验证核心玩法
2. 接入版本控制
3. 搭开发自循环

这套能力包默认主要服务于“已经进入持续开发阶段的 UE 项目”，所以实践重心会更多落在第 2 步和第 3 步。

但这只是场景适配，不是删除原文第一步。
如果未来用于新项目起盘，原型验证仍然应该保留在 Harness 的最前面。
