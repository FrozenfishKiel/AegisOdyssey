# Rule

## 作用

`Rule` 解决的是“AI 在动手之前，应该先知道什么”。

它承载的是最核心、最不能忘的硬约束，而不是大而全手册。

Rule 的职责是：

- 在任务开始前生效
- 用最少量的规则约束最关键的行为
- 把容易反复口头提醒的要求外置到工程系统里

Rule 不负责：

- 完整任务流程
- 项目全部背景知识
- 事后验证

这些应交给 `Skill / Task Flow`、`Script / Validation` 和 `MCP / Memory`。

## 设计原则

结合原文和当前 UE 场景，Rule 默认遵守下面几条原则：

1. 数量少  
   只保留最重要的硬约束，避免规则过多后注意力衰减。

2. 约束硬  
   不能写成“最好”“建议”“尽量”这种愿望清单。

3. 事前生效  
   Rule 的职责是让 AI 在开始前就知道边界，而不是任务结束时再补救。

4. 易于升级  
   如果某个坑反复出现，优先考虑能否升级成 Rule。

## UE 场景里的推荐 Rule 类型

对于 Unreal Engine 项目，Rule 可以优先约束这些高频遗漏点：

- 核心函数必须写中文注释
- 新增属性必须写中文注释
- 系统改动后必须补技术文档
- 改动后必须补冷启动测试文档
- 涉及蓝图交互时必须写清 C++ 类、蓝图父类和编辑器接线位置

这些要求的共同特点是：

- 高频
- 容易漏
- 一旦缺失就会影响后续接线或理解

## 和其他层的关系

- Rule 告诉 AI 应该怎么做
- Skill 告诉 AI 应该按什么顺序做
- Script 告诉 AI 做完了没有

如果一个要求更像“顺序”，不要写进 Rule。
如果一个要求更像“验证”，也不要写进 Rule。
